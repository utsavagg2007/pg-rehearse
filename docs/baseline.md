# Baseline setup and SQL contracts

Steps 4 and 5 are implemented. After full preflight and scoped role checks, `run`
loads accepted schema/fixtures inside the worker, verifies the seeded database,
and executes deployed contracts against a fresh baseline clone. Separate deployed
and candidate branches apply migrations before their contracts; see [rehearsal.md](rehearsal.md).

```sh
make worker-image
uv run --locked pg-rehearse run --config examples/orders/rehearsal.yml
```

A failing baseline returns **3**, preserves evidence and skips migrations. It does
not establish migration incompatibility. Successful baseline checks allow the
post-migration experiments to continue; final reports determine exit 0/1/3/4.
The complete flow conservatively stops after any failed baseline operation.

## Setup and deterministic fixtures

The host copies logical input names, accepted bytes and hashes. The worker repeats
the same preflight against those bytes, without filesystem reads. This preserves
contained symlink aliases and prevents edits after validation from changing a run.

Setup runs as the migration owner through the scoped setup login. One transaction
creates tables, inserts rows, resets identity sequences, verifies every table and
runs ANALYZE. Failure rolls back the setup transaction and skips contracts. The
receipt records schema_error, fixture_error or verification_error and SQLSTATE,
without PostgreSQL error text or failing row contents.

Parent tables load before children. Self-referencing rows load after their parent
rows; a row may reference itself. Cyclic dependencies across tables or rows are
rejected during preflight. Table declarations are reordered by dependencies while
the original SQL text for each statement is preserved. Column identifiers are
quoted and every fixture value is a parameter. Typed values reuse preflight
conversion for numeric, UUID, dates and timestamps.

Fixtures are explicit rows, with stable dependency ordering and no clock/global
random state. The declared seed is recorded. No additional generator format is
introduced. Readback checks row multisets and all column values, records verified
row counts, and hashes the canonical data independently of run IDs or row scan
order. Identical inputs reproduce the same data digest in independent databases.

Integer GENERATED BY DEFAULT AS IDENTITY is now accepted with default sequence
options. Fixtures must supply explicit identity IDs. Sequences resume above the
largest positive fixture ID; empty/all-negative sets start at 1. ALWAYS identity,
SERIAL and custom sequence options remain unsupported. See PostgreSQL 17
[identity columns](https://www.postgresql.org/docs/17/ddl-identity-columns.html) and
[sequence functions](https://www.postgresql.org/docs/17/functions-sequence.html).

## Contract execution

Operations execute in declared order as the workload login. Positional and named
Psycopg parameters are passed separately from SQL. Empty bindings become None,
which preserves literal percent signs. Ordinary SELECT, INSERT, UPDATE and DELETE
use the existing bounded SQL preflight; explicit identity override modes are rejected.

Each operation uses an independent rollback-only transaction, including successful
writes. Results and assertions are observed before rollback; a later probe sees
the original rows. Failed SQL rolls back before the next operation. Probes do not
model committed writes or dependencies between operations; rollout phases and
persistent sessions remain later work. PostgreSQL sequence advances survive
rollback, so generated IDs can advance between write probes in the same contract.
Fresh clones isolate separate baseline/deployed/candidate experiments. Transaction behavior follows the installed
[Psycopg transaction API](https://www.psycopg.org/psycopg3/docs/basic/transactions.html).

Every result records operation ID, application version, phase, success, optional
SQLSTATE and an explicit error category. SQL errors and assertion mismatches stay
separate. Columns, ordered rows and row_count are compared exactly for each
assertion declared by the operation. Booleans do not equal integers. Use ORDER BY
when a multirow expectation requires stable ordering. For commands without
RETURNING, row_count means affected rows; for result sets it means returned rows.

Numeric results use decimal strings, UUIDs use canonical strings, dates/timestamps
use ISO strings, and timestamptz uses UTC with +00:00. Expectations for these types
must use those string representations. JSON-native values preserve their types;
NULL is represented by null. Unsupported/nonfinite results explicitly fail.

SELECT uses a server cursor. Each probe has statement/lock settings, a total
operation alarm, and limits of 10000 rows and 1 MiB of normalized result data.
Result-limit failures roll back and do not poison subsequent probes. DML RETURNING
currently buffers in libpq before client limits are checked; the worker's memory
and wall-time budgets still apply. Large write-result streaming is not implemented.

Assertion evidence keeps values up to 1024 encoded bytes; larger values retain
SHA-256 and byte length after full comparison. This bounds receipts without
silently comparing only a prefix. Raw server exceptions are never included.

## Evidence and coverage

Worker response version 2 adds baseline setup, operation assertions and coverage
to the existing role probes. The coordinator rejects missing setup, wrong row
counts, wrong operation identities, missing/duplicate assertions, mismatched
expectations, invented success flags or coverage that disagrees with observations.
Required IDs are phase-qualified, such as baseline/deployed-v1/get-user. Completed
coverage means a result was recorded, including failures; success is separate.

Responses are limited to 8 MiB and worker logs rotate at 16 MiB. The baseline
receipt remains worker-evidence.json (0600); final cleanup remains manifest.json.
The full RunResult is analyzed only after teardown, then rendered as terminal,
JSON and Markdown reports. A complete baseline alone cannot pass a rehearsal.
Rebuild the worker image after source changes; older responses that lack the
required experiment evidence are rejected. See [rehearsal.md](rehearsal.md).
